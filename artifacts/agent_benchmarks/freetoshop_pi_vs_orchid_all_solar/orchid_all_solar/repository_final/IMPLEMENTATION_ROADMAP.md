# FreetoShop Implementation Roadmap

## Contract and status rules

This roadmap tracks the complete near-Photopea build contract. It does not
reduce the intended scope, and a polished UI or passing smoke test is not
evidence of parity. The current repository and its executable tests are the
implementation authority.

Every subsystem has exactly one maturity level:

- **Not started:** no production implementation.
- **Foundation only:** interfaces or a narrow first path exist, but ordinary
  product workflows do not depend on them comprehensively.
- **Partially integrated:** a real user workflow uses the subsystem, with
  documented feature, performance, or compatibility gaps.
- **Functionally complete:** the required behavior exists across ordinary
  workflows, but parity, stress, compatibility, or release hardening remains.
- **Compatibility-hardened:** broad corpora, cross-engine behavior, malformed
  inputs, migrations, and regression suites pass; operational release work may
  remain.
- **Production-ready:** the original definition of done is met, including
  performance, security, accessibility, documentation, and release evidence.

No subsystem is currently production-ready. Status changes require concrete
implementation, tests, benchmark or runtime evidence where relevant, and a
record of remaining limitations.

## Active critical path

1. Make tiled resources canonical for pixel layers, masks, editing, history,
   persistence, PSD decode, and export boundaries.
2. Connect exact edit bounds to a real tile render scheduler with dependency
   caching, progressive viewport work, mip levels, eviction, and cancellation.
3. Establish reproducible tri-engine browser performance and memory suites.
4. Continue incremental `App.tsx` decomposition as each workflow is touched.
5. Expand PSD support through preservation-first parsing before any PSD export.
6. Evolve the native container only after canonical tile ownership stabilizes.
7. Continue the remaining professional editor, compatibility, and production
   hardening contract without substituting shallow toolbar breadth for the
   critical path above.

## Imminent professional-editing queue

These are the next user-prioritized compatibility slices after the active M1/M2
infrastructure gate. Their order is intentional; a slice is complete only when
its editing workflow, history behavior, persistence, focused tests, and
tri-engine runtime path pass together.

1. **Clone Stamp:** sampled-source tiled strokes with aligned/unaligned modes,
   transformed-layer coordinates, selection/mask clipping, undo, and reopen.
2. **Healing Brush foundation:** sampled texture transfer with deterministic
   tone/color blending, bounded tile reads, selection clipping, undo, and
   reopen.
3. **Curves:** editable RGB composite curve with stable interpolation, live
   preview, adjustment-layer persistence, destructive application, and undo.
4. **Layer alignment/distribution/linking:** multi-layer targeting, canvas or
   selection reference bounds, deterministic alignment/distribution, persisted
   links, linked movement, and atomic undo.
5. **Perspective/distort:** four-corner transform preview/apply for layers and
   masks, bounded resampling, cancel, undo, and reopen.
6. **Brush dynamics and pressure:** pointer-pressure size/opacity mapping,
   deterministic mouse fallback, persisted controls/presets, and replayable
   stroke history.
7. **Select and Mask:** edge-refinement controls and preview modes that can
   output a selection or raster mask while preserving sparse coverage.
8. **Better text controls:** character/paragraph controls for ranges, font
   selection, size, leading, tracking, alignment, and persisted editable text.
